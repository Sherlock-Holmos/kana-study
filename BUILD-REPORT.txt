Japanese Study v13.0.0 - Stable Hashed Build
=============================================

Purpose
-------
Eliminate cross-version ES Module mixing caused by browser, Service Worker or CDN caching.
The user-visible regression that motivated this release was a production startup failure where
views/home.js requested getN5Completion while a stale core/metrics.js was served without that export.

Production architecture
-----------------------
1. Maintained source remains under src/.
2. scripts/build.mjs recursively resolves the ES Module dependency graph.
3. Every production JavaScript module is rewritten to reference content-hashed dependencies.
4. CSS, PWA manifest and icons also receive content hashes.
5. index.html references only hashed production assets.
6. build-manifest.json records the complete current source -> production mapping.
7. Service Worker cache name includes the deterministic buildId.
8. Hashed /assets/ resources are cache-first; HTML/stable files are network-first.
9. Service Worker registration uses updateViaCache: "none".
10. Old hashed files are allowed to remain in the repository for stale-CDN-index compatibility.
